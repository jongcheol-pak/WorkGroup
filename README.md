# WorkGroup (작업 그룹 런처)

PC에 설치된 앱들을 "작업 그룹"으로 묶고, 그 그룹을 Windows 11 작업 표시줄에 핀하여 클릭 한 번으로 그룹 안의 앱들을 아이콘 그리드 팝업에서 실행하는 WinUI 3 데스크톱 앱.

> **상태**: 코어·인프라·런처 + UI 전면 개편(NavigationView 셸 + Fluent) + 다국어(한/영/일/중 4개 언어) 완료. 상세는 [`plan.md`](plan.md) 참조.

## 기술 스택
- C# / .NET 10
- WinUI 3 (Windows App SDK), MSIX 패키징
- Windows 11

## 아키텍처 (DDD 레이어)
| 프로젝트 | TFM | 역할 |
|---|---|---|
| `src/WorkGroup.Domain` | net10.0 | 도메인 모델/불변식 (외부 의존 없음) |
| `src/WorkGroup.Application` | net10.0 | use case 서비스 + 인프라 인터페이스 |
| `src/WorkGroup.Infrastructure` | net10.0-windows10.0.19041.0 | WinRT/Win32 interop 구현 |
| `src/WorkGroup.App` | net10.0-windows10.0.19041.0 | WinUI 3 UI + DI + 런처 |

의존 방향: `App → Infrastructure → Application → Domain`

## 빌드 / 실행
```sh
# 빌드
dotnet build WorkGroup.slnx

# 단위 테스트
dotnet test WorkGroup.slnx
```
- 패키지 앱 GUI 실행: Visual Studio에서 `WorkGroup.App`을 시작 프로젝트로 두고 F5(MSIX 배포·디버그).
- 다국어 리소스(`.resw`)는 `src/WorkGroup.App/Strings/{언어}/Resources.resw`에 두며 .NET SDK가 PRIResource로 자동 포함한다. **증분 빌드는 새 `.resw` 키를 `resources.pri`에 재생성하지 못할 수 있으므로, 리소스를 추가·변경한 뒤에는 클린 빌드(`dotnet clean` 후 재빌드)를 권장한다**(VS F5 배포는 대개 정상).

## 화면 구성 (NavigationView 셸)
좌측 메뉴 + 우측 컨텐츠 레이아웃. WinUI 3 Gallery / Fluent 디자인(커스텀 TitleBar[앱 아이콘 + 제목] + Mica 백드롭, 라이트/다크 테마, `SettingsCard`, 공통 페이지 레이아웃). 디자인 토큰은 `src/WorkGroup.App/Resources/`(Spacing/ControlStyles).
- **작업 그룹**: 그룹 목록(순서 변경 핸들 + 그룹 아이콘 + 이름/멤버 앱 아이콘 2라인 + 수정·삭제 아이콘 버튼), 그룹 검색(이름·멤버 앱 이름), 상단 "그룹 추가". 카드 왼쪽 핸들(≡)을 끌어 **목록 순서 변경**(검색 중에는 핸들이 숨겨진다).
- **트레이 메뉴(시작)**: 등록한 폴더 목록(아이콘 + 이름 + 경로) 관리 — 폴더 검색, 추가(찾아보기로 폴더 선택), 수정(연필), 위치 열기/삭제(⋯ 메뉴), 팝업 설정(톱니), 카드 왼쪽 핸들(≡) 드래그로 **목록 순서 변경**(트레이 좌클릭 팝업의 표시 순서에 그대로 반영). 트레이 아이콘을 좌클릭하면 여기 등록된 폴더가 팝업으로 표시된다.
- **설정**(하단): 로그인 시 자동 시작 토글, 앱 테마(시스템/라이트/다크) 전환, 표시 언어(시스템 언어/한국어/English/日本語/中文(简体)) 선택 — 변경 시 확인 후 앱 재시작으로 적용. **초기화**: 작업 그룹 목록·트레이 메뉴 목록을 각각 전체 삭제(확인 다이얼로그 후, 작업 그룹은 생성된 바로가기·아이콘까지 정리).
- **정보**(하단): 앱 이름·버전(앱 이름 카드 오른쪽에 공식 홈페이지 링크 버튼), 오픈소스 라이선스 목록(이름+종류+링크).

## 핵심 기능
- **설치 앱 수집**: Win32(시작 메뉴 .lnk) + Store/UWP(`shell:AppsFolder`) 앱을 현재 사용자 기준으로 수집·검색.
- **앱 아이콘 추출**: Win32(.lnk/.exe 파일 경로)·Store/UWP(`shell:AppsFolder\{AUMID}`) 앱 모두 셸이 렌더한 아이콘(`IShellItemImageFactory`)을 추출한다 — 탐색기/시작 메뉴와 동일해 아이콘 누락이나 앱별 로고 여백 편차 없이 균일. 추출 실패 시 셸 썸네일/단색·기본 아이콘으로 폴백.
- **그룹 구성**: "그룹 추가/수정" 다이얼로그에서 상단 [아이콘][이름(20자)], "+"(앱 추가) 버튼으로 설치 앱을 골라 선택 목록에 담고, 그 오른쪽 **"파일 추가"(폴더 열기 아이콘) 버튼**으로 실행 파일(.exe/.lnk)을 직접 선택해 목록에 추가한다(항목별 삭제, 항목 사이 구분선). 선택 목록의 항목은 **드래그해 순서를 바꿀 수 있고**, 그 순서가 핀 팝업의 앱 배치 순서가 된다. 그룹 생성/편집/삭제. 선택 목록 위 왼쪽에는 등록된 앱 개수("앱 N개")가 표시된다. "+" 버튼 왼쪽의 **"팝업 이름 표시" 토글**로 그 그룹의 핀 팝업에 그룹 이름 헤더를 표시할지 여부를 그룹별로 설정한다(기본 숨김). 그룹 아이콘은 클릭 → **사용자 이미지**(파일 선택) 또는 **리소스 아이콘**(번들 이미지 그리드) 선택. 앱이 없거나 이름이 중복이면 추가가 차단됨. **수정 모드**에서는 이름이 읽기전용으로 표시되고 클릭하면 입력창으로 전환되며, 이름을 바꾸면 "작업 표시줄에 등록한 기존 항목을 제거하고 다시 등록을 해야 한다"는 안내가 입력 영역 아래에 표시된다(핀 표시 이름은 Windows 제약상 자동 변경 불가).
- **작업 표시줄 드래그 등록**: 그룹 항목을 작업 표시줄로 끌어 핀(.lnk). 핀된 아이콘은 실행 별칭 `WorkGroup.exe`를 `--group {id}` 인자로 호출.
- **작업 표시줄 핀 자동 유지·복구**: 핀이 가리키는 실행 별칭은 앱 업데이트마다 재생성되어 핀의 셸 링크 정보가 무효화될 수 있다(클릭 시 "이 항목을 열 수 없음"). 앱 시작 시 우리 핀을 찾아 별칭/인자/아이콘을 다시 써 자동 복구한다.
- **그룹 팝업 런처**: 핀된 아이콘 클릭 시 작업 표시줄 변에 접해 멤버 앱 아이콘을 나열한 팝업이 뜬다. 작업 표시줄 **위치에 따라 방향이 바뀐다** — 하단/상단이면 작업 표시줄 위/아래에 **가로 1행**, 좌측/우측이면 작업 표시줄 오른쪽/왼쪽에 **세로 1열**로 표시된다(아이콘 수에 맞춰 크기 자동 조정, 작업영역을 넘으면 가로 1행은 가로 스크롤·세로 1열은 세로 스크롤) → 클릭 시 앱 실행(Win32 셸 / 패키지 AUMID). 실행 파일이 삭제된 멤버(Win32)는 팝업에서 흐리게·비활성으로 표시되어 클릭되지 않는다. 상주 중에는 팝업 창과 앱 아이콘을 재사용·캐시해 두 번째부터 빠르게 표시한다. 표시될 때 팝업 창 자체가 작업 표시줄 쪽에서 떠오르며 콘텐츠가 페이드인하는 진입 애니메이션이 적용된다(방향은 작업 표시줄 위치에 따라 자동). 아이콘에 마우스를 올리면 앱 이름이 툴팁으로 표시되고, **우클릭하면 컨텍스트 메뉴**(열기 / 관리자 권한으로 실행 / 그룹 수정)가 뜬다. "관리자 권한으로 실행"은 Win32 앱만 가능하며 패키지 앱에서는 비활성화된다. "그룹 수정"은 메인 창을 열어 해당 앱이 속한 그룹의 편집 다이얼로그를 표시한다(메인 앱은 단일 인스턴스로 동작 — 이미 실행 중이면 기존 창에서 열린다). 또한 앱 아이콘 목록 **끝의 "+" 버튼**을 클릭하면 우클릭 "그룹 수정"과 동일하게 해당 그룹의 편집 다이얼로그를 연다(멤버가 없는 그룹에서도 표시된다). 팝업 상단 그룹 이름 헤더는 그룹의 "팝업 이름 표시" 설정에 따라 표시/숨김된다(단 좌/우 작업 표시줄의 세로 1열 팝업에서는 너비를 아이콘 폭에 맞추기 위해 헤더를 항상 숨긴다).
- **폴더 바로가기(트레이 좌클릭 팝업)**: "트레이 메뉴(시작)" 화면에 디스크 폴더를 등록해 두고, 트레이 아이콘 **좌클릭** 시 작업 표시줄 변 위에 등록 폴더 목록 팝업이 뜬다. 폴더 클릭 시 탐색기로 열고, 폴더에 마우스를 올리면 그 안의 파일/하위폴더가 2차 팝업으로 표시된다(파일 클릭 시 기본 앱으로 실행, 하위 폴더는 설정한 깊이까지 재귀). 디스크에서 삭제된(존재하지 않는) 폴더는 목록에서 흐리게·비활성으로 표시되어 클릭/호버되지 않는다. 팝업 **설정**(톱니)에서 열 개수(1~5: 1=세로 목록, 2~5=그리드), 하위 폴더 탐색 깊이(1~5), 숨김 파일/폴더 표시 여부를 조정한다. (기존 "작업 그룹"과는 별개 기능.)
- **테마**: 시스템/라이트/다크 선택, 설정에 영속(다음 실행에도 유지). 팝업 창에도 동일 적용.
- **다국어(i18n)**: 한국어/영어/일본어/중국어(간체) 4개 언어 지원. 모든 표시 문구는 리소스(`.resw`)로 관리하며 `{loc:Localize}` 마크업 익스텐션(XAML)과 `ILocalizer`(C#/인프라)로 조회한다. 설정의 "언어"에서 선택하며 기본값은 **시스템 언어**(OS 언어를 따름). 선택값은 설정에 영속되고, 변경 시 앱을 재시작해 전체 UI·시작 메뉴 표시 이름(매니페스트 `ms-resource`)에 반영한다. 앱 표시 이름은 한국어만 "작업 그룹 관리"이고, 그 외 언어(영어/일본어/중국어)는 모두 "WorkGroup Manager"로 표시된다.
- **자동 시작 / 트레이**: 로그인 시 자동 시작(토글). 트레이 아이콘 — **좌클릭**: 등록 폴더 목록 팝업, **우클릭 메뉴**: 열기(메인 창)/종료. 작업 표시줄(탐색기)이 다시 시작돼도 트레이 아이콘은 자동으로 복구된다. **스토어 업데이트로 OS가 앱을 종료해도, 업데이트 완료 후 트레이로 자동 복귀한다**(메인 창은 띄우지 않고 무음 상주).

## 데이터 위치
- 모든 데이터는 MSIX 가상화를 피해 `%USERPROFILE%\WorkGroup\` 아래에 저장된다.
- `groups.json`(전체 그룹 인덱스)은 루트에 둔다.
- `folders.json`(폴더 바로가기 목록)도 루트에 둔다. 폴더 팝업 설정(열 개수/깊이/숨김 표시)은 앱 LocalSettings에 저장된다.
- 그룹별 산출물은 **그룹 폴더** `Groups\{groupId}\`에 모은다(그룹 삭제 시 폴더째 제거):
  - `Groups\{groupId}\{그룹이름}.lnk` — 작업 표시줄 핀용 바로가기
  - `Groups\{groupId}\Icons\{groupId}.ico` — 작업 표시줄 핀 아이콘
  - `Groups\{groupId}\Icons\{groupId}.png` — 앱 내 목록 표시용(원본 해상도, 선명)

## 아키텍처 메모
- 그룹(핀) 클릭 시: 관리 화면/트레이가 **상주 중이면** 활성화를 상주 인스턴스로 redirect해 그 프로세스가 팝업을 즉시 표시(새 프로세스/초기화 비용 없음). 상주 인스턴스가 **없으면(콜드)** 별칭 exe가 새 인스턴스로 떠 팝업만 표시 후 종료. 상주 판정은 `AppInstance.GetInstances()`에서 메인 인스턴스 키(`WorkGroupMainInstance`)로 식별한다.
